# FIDO UAF Authenticator-Specific Module API

Version 1.2 · Proposed Standard · 2020-10-20 · [source](https://fidoalliance.org/specs/fido-uaf-v1.2-ps-20201020/fido-uaf-asm-api-v1.2-ps-20201020.html)

## Summary

The ASM API specifies the interface between a UAF Client and an Authenticator-Specific Module (ASM). The ASM is the platform component that knows how to reach a particular authenticator (over SPI, USB, Bluetooth and so on) and hides that from the client. The API is JSON-based, with these requests: GetInfo, Register, Authenticate, Deregister, GetRegistrations and OpenSettings. The document defines each request's input and output objects, the ASM status codes and how authenticator status codes map onto them, and what the ASM does internally for each request. That includes hashing the final challenge, building the TLV authenticator commands, managing KeyHandles and the KeyID database for bound authenticators, and checking the caller.

Platform bindings are given for Android (intent API with an AIDL alternative, plus a Java interface), iOS (C++ interface) and Windows. A security chapter covers KHAccessToken and access control. An optional chapter maps CTAP2 commands onto UAF authenticator commands. The authenticator side of each call is in Authenticator Commands; the client side is in the Protocol and client API documents.

**Who needs it:** authenticator vendors writing ASMs, UAF client and platform developers

**Changes from previous version:** `asmVersion` is now 1.2. New §6 CTAP2 Interface (optional) lets an ASM present its authenticator as an external CTAP2 authenticator over CTAP transports, and maps authenticatorMakeCredential, GetAssertion, GetNextAssertion, Cancel, Reset and GetInfo onto UAF commands. New Java ASM API for Android (§5.2) and C++ ASM API for iOS (§5.3), intended for KeyStore/KeyChain-based authenticators whose ASM runs inside the relying party app. New status UAF_ASM_STATUS_SYSTEM_INTERRUPTED (0x12). Register processing now checks that the appID matches the appID inside the final challenge. Register and Authenticate pass `ASMRequest.exts` to the authenticator as TAG_EXTENSION. The security chapter is renumbered from 6 to 7.
