# FIDO UAF WebAuthentication Assertion Format

Version 1.2 · Proposed Standard · 2020-10-20 · [source](https://fidoalliance.org/specs/fido-uaf-v1.2-ps-20201020/fido-uaf-webauthn-v1.2-ps-20201020.html)

## Summary

This UAF 1.2 document defines the WAV1CBOR assertion scheme, which lets a WebAuthn/CTAP2 authenticator be used through the UAF protocol. An ASM talks to the authenticator over CTAP2 and wraps the results in UAF assertion structures, so that a UAF server can register and authenticate the authenticator.

The registration assertion (TAG_WAV1CBOR_REG_ASSERTION) carries the WebAuthn authenticatorData with attested credential data concatenated with the client data hash, the attestation format name (`fmt`) and the attestation statement. The authentication assertion (TAG_WAV1CBOR_AUTH_ASSERTION) carries authenticatorData plus the client data hash, the AAGUID, the credential ID as the KeyID, and the signature. The processing rules describe how the ASM calls authenticatorGetInfo and the other CTAP2 commands, handles clientPin enrolment and builds the assertions, and how the FIDO Server verifies them, using the AAGUID for metadata lookup and policy matching. A final table maps CTAP2 error codes to ASM status codes.

This is a new document in UAF 1.2. It works together with the CTAP2 interface chapter of the ASM API 1.2, CollectedClientData in the Protocol 1.2, and the resident key and attestation conveyance extensions in the Registry 1.2.

**Who needs it:** ASM developers bridging CTAP2 authenticators into UAF, FIDO Server developers accepting such assertions
