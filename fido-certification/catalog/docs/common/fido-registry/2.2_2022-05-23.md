# FIDO Registry of Predefined Values

Version 2.2 · Proposed Standard · 2022-05-23 · [source](https://fidoalliance.org/specs/common-specs/fido-registry-v2.2-ps-20220523.html)

## Summary

Version of the FIDO Registry published with the May 2022 common specifications. It defines the shared user verification, key protection, matcher protection, attachment hint, display, algorithm, key format and attestation constants, each with a string form for metadata. It was released on the same date as the 2.1 Glossary, Security Reference, AppID and ECDAA documents. 2.3 later added the sync-fabric key protection and smart-card attachment hint.

**Who needs it:** authenticator vendors, FIDO server developers, certification applicants using 2022-era metadata

**Look here for:**
- Signature algorithm identifiers → §3.6.1 `#h4_authentication-algorithms`
- Attestation type constants → §3.7 `#h3_authenticator-attestation-types`

**Changes from previous version:** Adds `ALG_SIGN_ED448_EDDSA_SHA512_RAW` and renames `ALG_SIGN_SECP512R1_ECDSA_SHA512_RAW` to `ALG_SIGN_SECP521R1_ECDSA_SHA512_RAW` (correcting the curve name). Adds attestation types `ATTESTATION_ANONCA` (an anonymization CA issuing per-credential certificates, mapped to WebAuthn formats such as `apple` and `android-key`) and `ATTESTATION_NONE`. Also editorial fixes and reference updates.
