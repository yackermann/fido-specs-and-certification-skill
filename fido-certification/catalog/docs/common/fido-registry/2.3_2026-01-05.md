# FIDO Registry of Predefined Values

Version 2.3 · Proposed Standard · 2026-01-05 · [source](https://fidoalliance.org/specs/common-specs/fido-registry-v2.3-ps-20260105.html)

## Summary

The FIDO Registry of Predefined Values: the numeric and string constants for authenticator characteristics shared by UAF, FIDO2 and the Metadata Service. It defines user verification method flags (`USER_VERIFY_*`, with `_INTERNAL` / `_EXTERNAL` variants), key protection types (`KEY_PROTECTION_*`), matcher protection types, attachment hints (`ATTACHMENT_HINT_*`), transaction-confirmation display types, authentication algorithms (`ALG_SIGN_*`, from P-256 ECDSA through RSA-PSS/PKCS#1, SM2, Ed25519 and Ed448) with their allowed public key formats (`ALG_KEY_*`, including COSE), and attestation types (`ATTESTATION_BASIC_FULL`, `_BASIC_SURROGATE`, `_ECDAA`, `_ATTCA`, `_ANONCA`, `_NONE`). Each constant has a case-sensitive string form used in metadata.

Metadata Statements and MDS entries describe authenticators with these values: the key protection, matcher protection, user verification methods, attachment hints, algorithms and attestation types an applicant declares are all Registry constants. The Registry is expected to grow as new algorithms and authenticator characteristics are defined.

**Who needs it:** authenticator vendors (writing Metadata Statements), FIDO server and relying-party developers (policy and metadata processing), certification applicants, labs

**Look here for:**
- User verification method flags and the internal/external distinction → §3.1 `#h3_user-verification-methods`
- Key protection values, including multi-device (synced) keys → §3.2 `#h3_key-protection-types`
- Attachment hints (wired, wireless, NFC, smart card …) → §3.4 `#h3_authenticator-attachment-hints`
- Signature algorithm identifiers and encodings → §3.6.1 `#h4_authentication-algorithms`
- Public key representation formats → §3.6.2 `#h4_public-key-representation-formats`
- Attestation type constants → §3.7 `#h3_authenticator-attestation-types`

**Changes from previous version:** Adds `KEY_PROTECTION_SYNC_FABRIC` (0x0020, "sync_fabric") for keys designed to exist on several devices (multi-device credentials). When it is set, the authenticator has to set the WebAuthn backup-state flags and declare multi-device support in its Metadata Statement; the flag can be combined with SE/TEE/software protection for imported keys. Also adds `ATTACHMENT_HINT_SMART_CARD` (0x0200, "smart-card") for external authenticators that speak ISO 7816. The rest is reference status updates.
