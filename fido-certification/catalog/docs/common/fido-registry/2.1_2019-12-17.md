# FIDO Registry of Predefined Values

Version 2.1 · Proposed Standard · 2019-12-17 · [source](https://fidoalliance.org/specs/common-specs/fido-registry-v2.1-ps-20191217.html)

## Summary

Earliest catalogued common-specs (FIDO2-era) version of the FIDO Registry, published in December 2019. It extends the UAF-era constants for use with FIDO2 metadata, each constant gaining a case-sensitive string representation for metadata. It was the current Registry from December 2019 until the May 2022 release. 2.2 later added Ed448, corrected the P-521 name and added AnonCA and None attestation types.

**Who needs it:** authenticator vendors, FIDO server developers, certification applicants using 2019–2022 metadata

**Look here for:**
- `_INTERNAL` / `_EXTERNAL` user verification flags → §3.1 `#h3_user-verification-methods`
- Signature algorithms → §3.6.1 `#h4_authentication-algorithms`
- Attestation types → §3.7 `#h3_authenticator-attestation-types`

**Changes from previous version:** Substantive. Adds a string form for every constant. Renames user verification flags with an `_INTERNAL` suffix (same meaning, made explicit) and adds `USER_VERIFY_PASSCODE_EXTERNAL` and `USER_VERIFY_PATTERN_EXTERNAL`. Adds signature algorithms 0x000A–0x0012 (RSASSA-PSS SHA-384/512, RSASSA-PKCS1-v1_5 SHA-1/256/384/512, P-384 and "P-512" ECDSA, Ed25519) and `ALG_KEY_COSE`. Adds a new §3.7 with attestation types (basic full, basic surrogate, ECDAA, AttCA).
