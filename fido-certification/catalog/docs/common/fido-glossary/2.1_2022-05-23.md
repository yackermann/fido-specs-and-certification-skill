# FIDO Technical Glossary

Version 2.1 · Proposed Standard · 2022-05-23 · [source](https://fidoalliance.org/specs/common-specs/fido-glossary-v2.1-ps-20220523.html)

## Summary

The FIDO Alliance glossary of normative technical terms, shared by UAF, U2F, FIDO2 (CTAP/WebAuthn) and the certification documents. It is one alphabetical definitions chapter and does not try to cover every term: well-known terms are left to the referenced external glossaries. Entries cover protocol actors (FIDO Client, FIDO Server, ASM, Relying Party, RP ID), authenticator properties (AAGUID/AAID, attestation key, attestation types including ECDAA, user verification, user presence, key protection, matcher), execution environments used in security certification (Restricted, Allowed Restricted and Rich Operating Environments, TEE, Secure Element, trusted path, side-channel attack, Authenticator Security Parameter, security strength), and metadata (Metadata Statement, Metadata Service).

Use it when another FIDO specification or the Authenticator Security Requirements use a capitalized term without defining it. The other common specifications and the UAF, U2F and FIDO2 documents reference it normatively.

**Who needs it:** everyone reading FIDO specifications; certification applicants and labs in particular (security certification terms such as AROE and ASP)

**Look here for:**
- Definition of a FIDO term (AAGUID, ASM, attestation, user verification, …) → §3 `#h2_definitions`
- Security-certification terms (ROE/AROE, TEE, SE, ASP, security strength) → §3 `#h2_definitions`
- Enterprise attestation modes (vendor-facilitated vs platform-managed) → §3 `#h2_definitions`
- Scope of the glossary and where other terms come from → §2 `#h2_introduction`, A `#h2_references`

**Changes from previous version:** Substantive growth (about 30% longer). New entries include AAGUID, Relying Party Identifier / RP ID, Credential, ECDAA, Enterprise Attestation (EA mode 1 and 2), Metadata Statement and Metadata Service, Authenticator Model, Authenticator Security Parameter, Security Strength, Restricted / Allowed Restricted / Rich Operating Environment, Trusted Execution Environment, Secure Element, Trusted Path, Side Channel Attack, Revision Control System and Test of User Presence. "UAF Protocol Version" becomes "Unified Protocol Version", and several existing entries were reworded.
