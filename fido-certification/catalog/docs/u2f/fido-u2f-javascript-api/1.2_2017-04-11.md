# FIDO U2F JavaScript API

Version 1.2 · Proposed Standard · 2017-04-11 · [source](https://fidoalliance.org/specs/fido-u2f-v1.2-ps-20170411/fido-u2f-javascript-api-v1.2-ps-20170411.html)

## Summary

Defines the JavaScript API that relying-party web pages used to reach U2F tokens through the browser before WebAuthn. There are two levels: a required low-level MessagePort API with request and response dictionaries, and an optional high-level `u2f.register` / `u2f.sign` API that wraps it with callbacks. A registration request carries the AppID, one RegisterRequest per accepted protocol version and the already registered keys (so the client can skip tokens that are registered already). A sign request carries the AppID, a challenge and the registered keys. Responses return the protocol version, the raw token output and the client data, websafe-base64 encoded. The document also defines the transport hints (`bt`, `ble`, `nfc`, `usb`, `usb-internal`), the error codes (OK, OTHER_ERROR, BAD_REQUEST, CONFIGURATION_UNSUPPORTED, DEVICE_INELIGIBLE, TIMEOUT) and backward compatibility with the 1.0 `signRequests` form.

Browsers now expose WebAuthn instead, whose `appid` extension lets a site keep using credentials registered through this API. U2F 1.2 is the only certifiable U2F version.

**Who needs it:** relying parties & server developers (legacy U2F deployments), platform & client developers
