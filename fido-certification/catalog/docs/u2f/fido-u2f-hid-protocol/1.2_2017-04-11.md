# FIDO U2F HID Protocol Specification

Version 1.2 · Proposed Standard · 2017-04-11 · [source](https://fidoalliance.org/specs/fido-u2f-v1.2-ps-20170411/fido-u2f-hid-protocol-v1.2-ps-20170411.html)

## Summary

Specifies U2FHID, the framing that carries U2F raw messages over USB using the HID class. Messages are split into fixed-size HID reports: an initialization packet (4-byte channel ID, command byte with bit 7 set, 2-byte payload length) followed by sequence-numbered continuation packets. Channels let several host applications share one device; `U2FHID_INIT` on the broadcast channel allocates a channel ID and returns the protocol version, device version numbers and capability flags. The document defines transaction rules (one transaction at a time, busy and timeout handling, abort and resynchronization, packet sequencing), channel locking, the USB interface and endpoint descriptors, and the HID report descriptor with the FIDO usage page used for device discovery.

Commands: mandatory `U2FHID_MSG` (wraps a raw U2F APDU), `U2FHID_INIT`, `U2FHID_PING` and `U2FHID_ERROR`; optional `U2FHID_WINK` and `U2FHID_LOCK`; and a vendor-specific command range. CTAP 2.3 lists this document as superseded by its CTAPHID transport, which uses the same FIDO usage page; U2FHID may still be implemented for backward compatibility. U2F 1.2 is the only certifiable U2F version.

**Who needs it:** authenticator vendors (USB devices), platform & client developers, test labs
