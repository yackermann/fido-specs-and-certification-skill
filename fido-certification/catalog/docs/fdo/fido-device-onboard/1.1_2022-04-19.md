# FIDO Device Onboard Specification 1.1

Version 1.1 · Proposed Standard · 2022-04-19 · [source](https://fidoalliance.org/specs/FDO/FIDO-Device-Onboard-PS-v1.1-20220419/FIDO-Device-Onboard-PS-v1.1-20220419.html)

## Summary

FIDO Device Onboard 1.1 revises the 1.0 automatic IoT onboarding protocol. That protocol covers late binding of device credentials through Rendezvous Servers, Ownership Vouchers, and the DI/TO0/TO1/TO2 protocols. Version 1.1 fixes errata and also changes the CBOR wire format. Version 2.0 later replaced 1.1 with Delegation and a reordered TO2. FDO has its own FIDO certification program, separate from user-authentication certification.

**Who needs it:** IoT device vendors, owner/onboarding service and Rendezvous Server developers, FDO certification applicants

**Look here for:**
- List of 1.0 → 1.1 functional changes → Appendix F `#functional-changes`
- Errata fixed from 1.0 → Appendix F `#fixes-to-errata-in-10-document`
- Ownership Voucher format → §2.7 `#OVIntro`
- TO2 message details → §5.5 `#TO2`
- EPID attestation → Appendix D `#EPIDConsiderations`

**Changes from previous version:** Protocol version number added as the first element of the Ownership Voucher. New `OVEExtra` field. Voucher entries limited to 255. Fields that need post-processing are wrapped as `bstr .cbor`. `COSE_X509` renamed `X5CHAIN`. RSAPSS added, and RSA split into RSAPKCS and RSAPSS. Ciphersuites are now integers. TO2 adds negotiation of the maximum message size (capped at 65535) and a hash of `TO2.HelloDevice` inside `TO2.ProveOVHdr`. Canonical CBOR is now required. ServiceInfo nesting simplified. HTTP 302/307 redirects allowed for `TO1.HelloRV`. IANA-assigned numbers replace the 1.0 values. Also includes many errata fixes (EAT nonce/UEID values, IPv6 length, type corrections).
