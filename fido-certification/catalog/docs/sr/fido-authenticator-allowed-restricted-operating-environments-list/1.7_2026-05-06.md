# FIDO Authenticator Allowed Restricted Operating Environments List

Version 1.7 · Review Draft · 2026-05-06 · **ACTIVE** · [source](https://fidoalliance.org/specs/fido-security-requirements/fido-authenticator-allowed-restricted-operating-environments-list-v1.7-rd-20260506.html)

## Summary

Companion to the Security and Privacy Requirements. It explains how an authenticator splits into hardware, a Restricted Operating Environment (ROE) and the Authenticator Application, and when an ROE counts as an Allowed ROE (AROE). The §3 criteria are: vendor-controlled security configuration, secure boot, full isolation from the rich OS and outside components, a security-focused design, and strong isolation from any co-hosted apps. §4 is the official list of technologies with blanket AROE status for L2, each with its key protection type. The list covers TEEs on ARM TrustZone, Intel VT, SGX and ME/TXE; TEEs certified to the GlobalPlatform TEE PP; Windows VBS (VTL1); the AMD PSP secure world; TCG TPMs; secure elements; and, under conditions, an embedded CPU with in-package RAM. Additions require an SPWG vote. Bespoke designs can instead be described in detail and judged case by case by the Security Secretariat.

Status: ACTIVE, although the file is labelled Review Draft (2026-05-06). v1.6 is active until 2027-01-13; v1.5.1 has no expiry (L3/L3+ track).
