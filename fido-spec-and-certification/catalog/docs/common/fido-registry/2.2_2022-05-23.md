# FIDO Registry of Predefined Values

Version 2.2 · Proposed Standard · 2022-05-23 · [source](https://fidoalliance.org/specs/common-specs/fido-registry-v2.2-ps-20220523.html)

## Summary

Version of the FIDO Registry published with the May 2022 common specifications. It defines the shared user verification, key protection, matcher protection, attachment hint, display, algorithm, key format and attestation constants, each with a string form for metadata. It was released on the same date as the 2.1 Glossary, Security Reference, AppID and ECDAA documents. 2.3 later added the sync-fabric key protection and smart-card attachment hint.

**Who needs it:** authenticator vendors, FIDO server developers, certification applicants using 2022-era metadata

**Look here for:**
- Signature algorithm identifiers → §3.6.1 `#h4_authentication-algorithms`
- Attestation type constants → §3.7 `#h3_authenticator-attestation-types`

**Changes from previous version:** Adds `ALG_SIGN_ED448_EDDSA_SHA512_RAW` and renames `ALG_SIGN_SECP512R1_ECDSA_SHA512_RAW` to `ALG_SIGN_SECP521R1_ECDSA_SHA512_RAW` (correcting the curve name). Adds attestation types `ATTESTATION_ANONCA` (an anonymization CA issuing per-credential certificates, mapped to WebAuthn formats such as `apple` and `android-key`) and `ATTESTATION_NONE`. Also editorial fixes and reference updates.

## Reading guide

**Use this version when:** you handle FIDO2/CTAP-era metadata written against the May 2022 common specifications (MDS 3.0 era), or you need to know which constants existed before 2.3. Suite: FIDO2 / common specs 2.x.

**Differences from 2.3 (latest):** 2.2 and 2.3 are nearly identical. 2.2 does not have `KEY_PROTECTION_SYNC_FABRIC` (0x0020) in §3.2 `#h3_key-protection-types`, so it gives no way to declare multi-device (synced) keys and no backup-flag rule. It also does not have `ATTACHMENT_HINT_SMART_CARD` (0x0200) in §3.4 `#h3_authenticator-attachment-hints`. Every other constant, value and string is the same, and the rest of the differences are reference updates.

**Differences from 2.1:** 2.2 fixes real errors in 2.1's §3.6.1 `#h4_authentication-algorithms`:
- The secp256k1 COSE alg becomes -47 (2.1 said 7).
- 0x000B gets its own string "rsassa_pss_sha512_raw" (2.1 reused "rsassa_pss_sha256_raw").
- 0x0011 is renamed from `SECP512R1` / "secp512r1_ecdsa_sha256_raw" to `ALG_SIGN_SECP521R1_ECDSA_SHA512_RAW` / "secp521r1_ecdsa_sha512_raw".
- 2.2 adds `ALG_SIGN_ED448_EDDSA_SHA512_RAW` (0x0013).

In §3.7 `#h3_authenticator-attestation-types` it adds `ATTESTATION_ANONCA` (0x3E0C) and `ATTESTATION_NONE` (0x3E0B).

**Section by section:** structure as in 2.3; see that page's reading guide.

**Watch out for:** the "This version" link in the document header points to a v2.1 URL dated 20220523, which looks like a typo. The document itself is 2.2.
