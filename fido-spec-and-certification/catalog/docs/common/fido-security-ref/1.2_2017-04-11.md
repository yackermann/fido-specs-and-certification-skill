# FIDO Security Reference

Version 1.2 · Proposed Standard · 2017-04-11 · [source](https://fidoalliance.org/specs/fido-u2f-v1.2-ps-20170411/fido-security-ref-v1.2-ps-20170411.html)

## Summary

Copy of the FIDO Security Reference shipped with the U2F 1.2 suite. It analyzes UAF and U2F security: attack classification, UAF security goals (U2F shares them except transaction non-repudiation), measures, assumptions, and a threat catalogue covering the client, the authenticator, the relying party, the TLS channel, the supply chain, and UAF-as-second-factor/U2F. Version 2.1 later broadened it to FIDO2/WebAuthn and roughly doubled the security measures.

**Who needs it:** certification applicants, labs and vendors working against the 2017 suites

**Look here for:**
- UAF security goals → §4 `#h2_uaf-security-goals`
- Security assumptions → §6 `#h2_uaf-security-assumptions`
- U2F/second-factor threats → §7.5 `#h3_threats-specific-to-uaf-with-a-second-factor-u2f`

**Changes from previous version:** Mostly editorial. One normative-adjacent addition: a note that physical attacks on the authenticator, after which the legitimate user keeps using it, are not explicitly covered. Reference URLs were also updated.

## Reading guide

**Use this version when:** you read U2F 1.2 / UAF 1.2-era (April 2017) material, or older Security Requirements editions that cite SG/SM/SA/T numbering from before 2.1. Suite: UAF 1.2 / U2F 1.2.

**Differences from 2.1 (latest):** substantive.
- Scope is UAF and U2F only, with no WebAuthn/CTAP (§2 `#h2_introduction`).
- §4 `#h2_uaf-security-goals` has SG-1–SG-15. SG-16 (assessable security) is missing.
- §5 `#h2_fido-security-measures` has only SM-1–SM-15, so none of the authenticator-implementation measures (allowed crypto, side channel, fault injection, trusted path, …) appear. SM-13 is a UAF-only Key Handle Access Token, and SM-14 is "AppID Separation" with no RP ID.
- §6 `#h2_uaf-security-assumptions` has seven assumptions. The extra one (SA-4) assumes a secure display that cannot be spoofed or tampered with. Because of it, 1.2's SA-5–SA-7 correspond to 2.1's SA-4–SA-6, so check the number before citing.
- §7 has 39 threats against 2.1's 66. The client section has a "Creating a Fake Client" subsection (§7.1.3 `#h4_creating-a-fake-client`, T-1.3.1 Malicious FIDO Client, which 2.1 renumbers to T-1.2.11).
- Authenticator threats stop at T-1.4.14 and sit under §7.1.4 `#h4_threats-to-fido-authenticator`. RP threats are in §7.2 `#h3_threats-to-relying-party` with no challenge-characteristics subsection. Infrastructure is §7.4 `#h3_threats-to-the-infrastructure`, and second-factor threats are §7.5 `#h3_threats-specific-to-uaf-with-a-second-factor-u2f` with no T-5.1.4.
- There is no separate attack-classes list.

**Differences from 1.1:** one added note in §3 `#h2_attack-classification`: physical attacks after which the legitimate user keeps using the authenticator are not covered. Otherwise the text is the same.

**Section by section:** §3 attack classes AC1–AC6 and the goal/measure mapping table (§5.1 `#h3_relation-between-measures-and-goals`) work as in 2.1, just with fewer entries; see the 2.1 page's reading guide.
