# FIDO Metadata Statement

Version 3.1.1 · Proposed Standard · 2026-01-05 · [source](https://fidoalliance.org/specs/mds/fido-metadata-statement-v3.1.1-ps-20260105.html)

## Summary

The FIDO Metadata Statement specification defines the JSON document that describes an authenticator model, so that servers and relying parties can interoperate with it and make risk decisions. A statement is identified by AAID (UAF), AAGUID (FIDO2) or attestation certificate key identifiers. It declares the protocol family and versions (`upv`), supported algorithms and public key encodings, and attestation types. It also covers user verification methods with accuracy descriptors (code, biometric, pattern), key and matcher protection, and transaction confirmation display. The statement also carries the attestation root certificates that servers use as trust anchors. Some fields serve passkey providers and synced credentials: light and dark icons and provider logos (SVG profile rules in §4.1), `multiDeviceCredentialSupport`, an embedded `authenticatorGetInfo`, and `cxConfigURL` for credential exchange. The schema version is 3. Allowed values come from the FIDO Registry of Predefined Values.

Vendors submit statements during FIDO certification. The Metadata Service then distributes them inside its signed BLOB. Statements are meant to stay stable, and a major change in functionality, such as a new user verification method, requires a new model identifier. This document does not state what changed in 3.1.1.

**Who needs it:** authenticator and passkey-provider vendors (writing statements), FIDO server developers and relying parties (consuming them), certification applicants
