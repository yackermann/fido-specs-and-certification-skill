# Client to Authenticator Protocol (CTAP)

Version 2.2 · Proposed Standard · 2025-07-14 · [source](https://fidoalliance.org/specs/fido-v2.2-ps-20250714/fido-client-to-authenticator-protocol-v2.2-ps-20250714.html)

## Summary

CTAP 2.2 extends CTAP 2.1 mainly for phones acting as authenticators and for enterprise PIN policy. It defines the hybrid transport: a QR code or stored state starts the connection, BLE advertisements prove proximity, and data travels through a tunnel service or a local link. It also adds a persistentPinUvAuthToken, JSON-based messages over hybrid (used for Digital Credentials API requests), and a PIN complexity policy feature. The specification does not define a `FIDO_2_2` version string, so 2.2 features are detected through getInfo members and extensions rather than `versions`.

**Who needs it:** authenticator vendors (especially phone/hybrid authenticators), platform & client developers, enterprise relying parties enforcing PIN policy

**Look here for:**
- How hybrid (QR-initiated and state-assisted) connections work → §11.5 `#sctn-hybrid`
- persistentPinUvAuthToken state → §6.5.2.2 `#authnrClientPin-globalState-persistent-puat`
- Enforcing a PIN complexity policy → §7.5 `#sctn-feature-descriptions-pinComplexityPolicy`
- New getInfo members (0x16–0x1D) → §6.4 `#authenticatorGetInfo`
- largeBlob, hmac-secret-mc and thirdPartyPayment extensions → §12 `#sctn-defined-extensions`

**Changes from previous version:** Added the hybrid transport (§11.5) and a persistentPinUvAuthToken with a `pcmr` permission (`perCredMgmtRO` option). Added JSON-based messages (§7.6) and the Set PIN Complexity Policy feature (§7.5). New extensions: largeBlob, pinComplexityPolicy, hmac-secret-mc and thirdPartyPayment. New getInfo members: attestationFormats, uvCountSinceLastPinEntry, longTouchForReset (stated here as a 10-second touch), encIdentifier, transportsForReset, pinComplexityPolicy, pinComplexityPolicyURL and maxPINLength.

## Reading guide

**Use this version when:** you need the 2.2 text for products or platforms built during its short life (July 2025 to February 2026). One example is a phone authenticator implementing hybrid or the Digital Credentials JSON messages to this edition. For new work, use 2.3, which keeps everything here and adds to it. For L3/L3+ certification the protocol baseline is CTAP 2.1 (2.1-errata), which Security Requirements 1.5.1 pairs with, not 2.2.

**Differences from 2.1:**
- persistentPinUvAuthToken (§6.5.2.2 `#authnrClientPin-globalState-persistent-puat`): a second token that holds only the new `pcmr` permission (0x40, read-only credential management). It is requested through the existing getPinUvAuthTokenUsing…WithPermissions subcommands and is gated by the `perCredMgmtRO` option. Credential management reads (§6.8 `#authenticatorCredentialManagement`) accept cm or pcmr. getInfo `encIdentifier` is derived from this token.
- PIN complexity policy (§7.5 `#sctn-feature-descriptions-pinComplexityPolicy`): supporting it MUST include ClientPIN, setMinPINLength and minPinLength. The policy is reported by the pinComplexityPolicy extension (§12.6 `#sctn-pincomplexitypolicy-extension`) and reset to defaults on reset.
- JSON-based messages (§7.6 `#sctn-feature-descriptions-jsonBasedMessages`): JSON-schema requests and responses for Digital Credentials API calls. Support is signalled by `dc` in the hybrid post-handshake message, not in getInfo.
- Hybrid transports (§11.5 `#sctn-hybrid`): QR-initiated (§11.5.1 `#hybrid-qr-initiated`) and state-assisted (§11.5.2 `#hybrid-state-assisted`) connections through a tunnel service, with BLE adverts as a proximity check and Noise handshakes.
- New extensions: largeBlob (§12.4 `#sctn-largeBlob-extension`), hmac-secret-mc (§12.8 `#sctn-hmac-secret-make-cred-extension`) and thirdPartyPayment (§12.9 `#sctn-thirdPartyPayment-extension`). makeCredential gains `attestationFormatsPreference` (0x0B), and getInfo gains members 0x16–0x1D (§6.4 `#authenticatorGetInfo`).

**Differences from 2.3:** 2.3 adds the Long touch for Reset feature and its authenticatorConfig subcommand, getInfo members 0x1E–0x1F, the `FIDO_2_3` version string and hybrid data-transfer subsections. In 2.2, `longTouchForReset` (0x18) is a plain boolean that means a 10-second touch, and no feature section backs it.

**Watch out for:** §9 `#mandatory-features` applies to authenticators listing `FIDO_2_2`. But the versions list in §6.4 `#authenticatorGetInfo` defines only `FIDO_2_0`, `FIDO_2_1`, `FIDO_2_1_PRE` and `U2F_V2`, and 2.3 confirms `FIDO_2_2` was never defined. Detect 2.2 features by their getInfo members and options. Most of §11.5 is prose and Go sample code with few MUST statements, so check the prose carefully before treating anything there as a test requirement.

**Section by section:** structure as in 2.3 apart from the items above; see that page's reading guide.
