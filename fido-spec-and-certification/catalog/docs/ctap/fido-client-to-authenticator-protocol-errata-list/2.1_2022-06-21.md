# CTAP 2.1 Errata

Version 2.1 · Proposed Standard · 2022-06-21 · [source](https://fidoalliance.org/specs/fido-v2.1-ps-20210615/fido-client-to-authenticator-protocol-v2.1-errata-20220621.html)

## Summary

This is the FIDO Alliance errata list for CTAP 2.1, dated 2022-06-21. For each correction it gives the affected section of the 2021-06-15 CTAP 2.1 Proposed Standard, the reason for the change, and the original and corrected text side by side. It has three entries:

- NFC user presence (spec §5 Terminology): adds a defined error response when the platform sends a zero-length pinUvAuthParam. The authenticator returns CTAP2_ERR_PIN_NOT_SET or CTAP2_ERR_PIN_INVALID and does not consume the NFC userPresent flag. This keeps multi-authenticator CTAP 2.0 platforms working.
- getInfo option IDs (spec §6.4): says the text and links for userVerificationMgmtPreview were wrong, but the original and corrected text it prints read the same; only the links differ.
- PRF values (spec §6.5.8): states that the authenticatorClientPIN row is removed and values are added for bioEnrollment and credentialManagement, but prints only the original table, with no corrected one. Read the corrected table in the 2.1 errata edition.

The same corrections are already merged into the CTAP 2.1 errata edition (`fido-client-to-authenticator-protocol`, version `2.1-errata`). Use this list to see exactly what changed, and use the errata edition as the normative text.

**Who needs it:** authenticator vendors and labs checking CTAP 2.1 implementations against corrected behaviour, platform developers handling NFC authenticators

**Look here for:**
- Which error to return for a zero-length pinUvAuthParam over NFC → §2 `#section-5-terminology`
- The getInfo option entry (links only) → §3 `#section-64-authenticatorgetinfo-0x04`
- What changed in the PRF argument patterns (original table only) → §4 `#section-658-prf-values-used`

## Reading guide

**Start here:** §1 Introduction `#intro` (one line: this is the errata for CTAP 2.1). Then read the three numbered entries. Each one links to a section of the 2021-06-15 CTAP 2.1 PS, says why it changed, and gives the original and corrected text.

**Section by section:**
- §2 Section 5 Terminology `#section-5-terminology`: the substantive fix. It concerns NFC (and ISO7816) authenticators whose only user gesture is the tap. On makeCredential/getAssertion with user presence requested, a zero-length pinUvAuthParam must now return CTAP2_ERR_PIN_NOT_SET (no PIN) or CTAP2_ERR_PIN_INVALID (PIN set), and it must not consume the NFC userPresent flag. Without the flag, the authenticator now ends with CTAP2_ERR_UP_REQUIRED; the original text named no error. The added note explains why: CTAP 2.0 platforms with several authenticators attached use this probe, and consuming the flag breaks them.
- §3 Section 6.4 authenticatorGetInfo `#section-64-authenticatorgetinfo-0x04`: the stated reason is incorrect text and links for userVerificationMgmtPreview. In the extracted text, though, the original and corrected `uv` option rows read the same; only the hyperlink targets differ. Treat it as editorial.
- §4 Section 6.5.8 PRF values used `#section-658-prf-values-used`: the reason says the authenticatorClientPIN row was removed and values were added for bioEnrollment and credentialManagement. Only the original table appears in this document. The corrected table (no clientPIN row; adds bio 0106 and credMgmt 07) is in the CTAP 2.1 errata edition.

**What matters most:**
- For NFC authenticator certification, the §2 behaviour is the testable change. Return the PIN error for a zero-length pinUvAuthParam without spending the tap, and return UP_REQUIRED when no tap is available (§2 `#section-5-terminology`).

**Watch out for:**
- §4 `#section-658-prf-values-used` has no corrected text. Use the 2.1 errata edition for the normative table.
- CTAP 2.2 and 2.3 do include the §2 NFC fix in their Terminology section. Their PRF table, however, matches the uncorrected 2.1 original: the clientPIN row is back and the bio 0106 and credMgmt 07 rows are missing. The errata correction did not carry forward.
- This list only covers 2.1. Later CTAP versions have no errata list in the catalog.

**Related documents:** `fido-client-to-authenticator-protocol` version `2.1-errata` (normative merged text), `2.1` (the text being corrected), and `2.3` (current; check which fixes carried forward).
