# FIDO Authenticator Metadata Requirements

Version 1.6 · Final Document · 2025-03-12 · **ACTIVE until 2027-01-13** · [source](https://fidoalliance.org/specs/fido-security-requirements/fido-authenticator-metadata-requirements-v1.6-fd-20250312.html)

## Summary

v1.6 (Final, 2025-03-12) of the Metadata Requirements. It lists the Metadata Statement fields that are mandatory and verified during Authenticator Certification, and covers optional MDS publication after certification. It references Metadata Statement / MDS 3.1. Status: ACTIVE until its sunset on 2027-01-13.

**Who needs it:** authenticator vendors, FIDO-accredited security labs

**Look here for:**
- Mandatory functional fields → Functional Metadata Fields `#functional-metadata-fields`
- Mandatory security fields → §3 `#h2_security-metadata-fields`
- Biometric fields → §4 `#h2_biometric-metadata-fields`

**Changes from previous version:** Editorial only. The text matches v1.5.1 apart from the version number.

## Reading guide

**Use this version when:** you certify against the v1.6 Security Requirements set before its sunset on 2027-01-13. It is also the field list to use if the metadata was prepared for that set.

**Differences from v1.7** (from a line-by-line comparison):
- Functional Metadata Fields `#functional-metadata-fields` does not list `multiDeviceCredentialSupport`.
- §3 `#h2_security-metadata-fields` does not list `fipsRevision` or `fipsPhysicalSecurityLevel`.
- The normative references point to Metadata Statement and MDS 3.1 (2025-05-21) rather than 3.1.1 (2026-01-05).
- Everything else is word-for-word the same: the process rules in §2 `#h2_introduction`, the other field rows, §4 `#h2_biometric-metadata-fields` and §5 `#h2_use-of-metadata-service-1.1-status-dictionary`.

**Differences from v1.5.1:** none apart from the version number and dates; the texts are identical.

**Section by section:** structure as in v1.7; see that page's reading guide. The same naming mismatches apply: several rows use type names or older field names, and `attestationRootCertificate` is limited to ECDAA here while the Metadata Statement makes it required for non-ECDAA attestation.
