# FIDO Authenticator Security and Privacy Requirements

Version 1.6 · Final Document · 2025-03-12 · **ACTIVE until 2027-01-13** · [source](https://fidoalliance.org/specs/fido-security-requirements/fido-authenticator-security-requirements-v1.6-fd-20250312.html)

## Summary

v1.6 (Final, 2025-03-12) of the authenticator requirements, now titled Security and Privacy Requirements. It keeps the same structure as v1.7: requirements with VQ, calibration, companion-program and per-level test-procedure boxes. It adds §3.2.4 on passkey backup and syncing. Status: ACTIVE until its sunset on 2027-01-13. v1.7 is the newest active version. v1.5.1 is a separate CTAP 2.1 branch that FIDO requires for L3/L3+.

**Who needs it:** authenticator vendors and certification applicants, FIDO-accredited security labs

**Look here for:**
- Requirement entry layout and VQ boxes → §1.4 `#h3_how-to-read-this-document`
- Security levels L1–L3+ → §2.1 `#h3_security-levels`
- Companion programs, including PP 0117 for L3/L3+ → §2.2 `#h3_certification-and-companion-programs`
- Requirements for backup-eligible (synced) credentials → §3.2.4 `#h4_backup-and-syncing`
- Version-by-version changes → Appendix A `#h2_differences-between-versions`

**Changes from previous version:** Compared with v1.5. v1.5.1 is a later, parallel branch and does not contain these changes. The companion-program and calibration boxes are reworked. A new L3/L3+ companion program based on PP 0117 (3S in SoC) is added. New passkey requirements cover multi-device credentials (1.12, 2.1.21) and Backup Eligible Authenticator Security Parameters (2.4.1, 2.4.2), plus requirement 5.10. Requirement 3.4 now states that using cached user presence ends the cache period. v1.6 does not include the GlobalPlatform FIDO2 SE companion program from v1.5.1.

## Reading guide

**Use this version when:** you are certifying against SR 1.6 before its sunset (the catalog lists it ACTIVE until 2027-01-13), or you maintain a product already certified against it. It is the first version with the passkey (multi-device credential) requirements and the PP 0117 (3S in SoC) companion program.

**Differences from 1.7:** The requirement chapter is otherwise identical apart from formatting. Missing from this version:
- 8.5, which requires bumping the firmware version on any binary change (§3.8 `#h3_self-tests-and-firmware-updates`).
- 10.3 (no misuse of protocol fields) and 10.4, the FIDO Reset deletion list (§3.10 `#h3_operational-guidance`).
- The L2 VQ and Test Procedure boxes on 2.1.15 (§3.2.1 `#h4_documentation`).

In the L2 calibration of 3.8 (§3.3 `#h3_authenticator-s-test-for-user-presence-and-user-verification`), external UV must be declared in both the metadata and the UVM extension, without 1.7's "if supported".

**Differences from 1.5.1 (the CTAP 2.1 branch):** §1.4 `#h3_how-to-read-this-document` and §2.2 `#h3_certification-and-companion-programs` replace the per-program boxes with per-PP boxes: IC PP, 3S in SoC PP, Java Card PP and TEE PP. They use the vocabulary NOT COVERED / PARTIALLY COVERED / OPTIONALLY COVERED instead of "linked to" / "fulfilled by". The GP FIDO2 SE program is absent. New or changed requirements:
- 1.12 (Device Public Key extension) and 2.1.21 (BE/BS flags).
- §3.2.4 `#h4_backup-and-syncing` (2.4.1/2.4.2, BEASP confidentiality).
- 2.2.6 (Device Identifier from an allowed RNG).
- 5.10 (nothing hidden in allow/exclude lists).
- 3.4: using the cached UP ends the cached period.
- 2.1.14 now applies from L1 and adds the none/self/Device Public Key attestation rules.
- 2.1.15 is lowered from L2+ to L2.
- 1.7 binding now covers FIDO2 RP IDs, not only UAF KHAccessToken.
- 3.10 now names BioLevel 1+/2+.

The 1.5→1.6 entry in Appendix A `#new-security-requirements-are-added-to-deal-with-passkeys` also lists a requirement 2.4.3, which does not exist in the body.

**Section by section:** the structure is as in 1.7; see that page's reading guide. Version-specific anchors: §3.2.4 `#h4_backup-and-syncing` and the PP 0117 entry `#a-new-companion-program-is-available-for-l3-l3-the-pp-0117-3s-in-soc-.x`. The §3.1 note still calls 2.1.15 "L2+ and higher", contradicting its header.
