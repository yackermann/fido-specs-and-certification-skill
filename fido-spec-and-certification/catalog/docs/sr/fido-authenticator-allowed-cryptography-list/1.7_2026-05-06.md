# FIDO Authenticator Allowed Cryptography List

Version 1.7 · Review Draft · 2026-05-06 · **ACTIVE** · [source](https://fidoalliance.org/specs/fido-security-requirements/fido-authenticator-allowed-cryptography-list-v1.7-rd-20260506.html)

## Summary

Companion list to the Security and Privacy Requirements. It names the cryptographic algorithms FIDO accepts inside a certified authenticator and gives each one the security strength used to compute the authenticator's Overall Claimed Security Strength. It does not change which algorithms the FIDO protocols allow. §3 is organised by function: confidentiality, hashing, data authentication, key protection, random number generation, key agreement, key derivation, signatures and anonymous attestation. The RNG section sets requirements for TRNG/NRBG and DRBG designs and accepts RNGs validated under Common Criteria, FIPS 140-2 or FIPS 140-3. Post-quantum entries are included: ML-KEM-512/768/1024 for key agreement and ML-DSA-44/65/87 for signatures, with NIST quantum security categories explained in §3.1. §2 sets the conditions for proposing a new algorithm: at least 112-bit strength, non-proprietary, endorsed by a recognised standards body, and publicly reviewed.

Status: ACTIVE, although the file is labelled Review Draft (2026-05-06). v1.6 is active until 2027-01-13, and v1.5.1 goes with the L3/L3+ track.

**Who needs it:** authenticator vendors filling in the VQ crypto answers, FIDO-accredited security labs

**Changes from previous version:** No change to the algorithm tables. The PQC narrative now names HQC as the next NIST KEM to be standardised, and the NIST IR 8547 reference is corrected. Otherwise only status and boilerplate change.
