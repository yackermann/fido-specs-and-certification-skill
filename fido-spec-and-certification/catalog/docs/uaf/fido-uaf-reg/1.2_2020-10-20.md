# FIDO UAF Registry of Predefined Values

Version 1.2 · Proposed Standard · 2020-10-20 · [source](https://fidoalliance.org/specs/fido-uaf-v1.2-ps-20201020/fido-uaf-reg-v1.2-ps-20201020.html)

## Summary

The UAF Registry of Predefined Values collects the identifiers and constants that only UAF uses. Values shared across FIDO families (algorithms, key encodings, user verification methods and so on) are in the separate FIDO Registry. This document defines the assertion scheme names (the default is UAFV1TLV), the tags that appear in UAF protocol messages (0x3E01 to 0x3E06), and the predefined extensions. For each extension it gives the identifier, the fail-if-unknown flag, the data format and the processing expected from the server, client, ASM and authenticator. It also defines the UAF Application Identifier (AID) used to select the UAF applet on Secure Elements.

The extensions are user verification method (`fido.uaf.uvm`), user ID (`fido.uaf.userid`), Android SafetyNet (`fido.uaf.safetynet`), Android Key Attestation (`fido.uaf.android.key_attestation`), user verification caching (`fido.uaf.uvc-req` / `fido.uaf.uvc-resp`), require resident key (`fido.uaf.rk`) and attestation conveyance (`fido.uaf.ac`). Authenticators declare supported extensions in their Metadata Statement.

**Who needs it:** authenticator vendors, ASM and client developers, FIDO Server developers

**Look here for:**
- Protocol tag values → §4.1 `#h3_tags-used-in-the-protocol`
- Asking for or confirming a specific user verification method → §5.1 `#h3_user-verification-method-extension`
- Android Key Attestation in UAF registration → §5.4 `#h3_android-key-attestation`
- Letting an authenticator reuse a recent user verification → §5.5 `#h3_user-verification-caching`
- Extensions for integrating CTAP2 authenticators → §5.6 `#h3_require-resident-key-extension`, §5.7 `#h3_attestation-conveyance-extension`
- UAF applet AID for Secure Elements → §6.1 `#h3_fido-uaf-application-identifier-aid`

**Changes from previous version:** Chapter 5 is renamed from "Predefined (untagged) Extensions" to "Predefined Extensions" and grows from two extensions (SafetyNet, Android Key Attestation) to seven. The new ones are user verification method; user ID; user verification caching, with new tag TAG_USER_VERIFICATION_CACHING 0x0108; require resident key, with new tag TAG_RESIDENT_KEY 0x0109; and attestation conveyance (`direct`, `indirect` or `none`). The last two exist to ease integration of CTAP2 authenticators. New protocol tags TAG_APCV1CBOR_AUTH_ASSERTION (0x3E05) and TAG_APCV1CBOR_SIGNED_DATA (0x3E06) support the Android Protected Confirmation assertion format. TAG_ATTESTATION_BASIC_FULL, TAG_ATTESTATION_BASIC_SURROGATE and TAG_ATTESTATION_ECDAA (0x3E07–0x3E09) are no longer listed here.
