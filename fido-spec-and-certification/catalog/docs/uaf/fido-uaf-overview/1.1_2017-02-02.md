# FIDO UAF Architectural Overview

Version 1.1 · Proposed Standard · 2017-02-02 · [source](https://fidoalliance.org/specs/fido-uaf-v1.1-ps-20170202/fido-uaf-overview-v1.1-ps-20170202.html)

## Summary

The 1.1 edition of the UAF Architectural Overview. UAF 1.1 is the version FIDO lists for certification (1.0 is sunset and not catalogued). It is the non-normative introduction to UAF: components (client, server, ASM, authenticator, metadata validation), the registration, authentication, step-up, transaction confirmation and deregistration flows, the reading list for the UAF documents, privacy, and how UAF relates to other technologies. Its body text is the same as the 1.2 edition apart from dates and links, so either edition can be read.

**Who needs it:** anyone new to UAF, including applicants preparing a UAF 1.1 certification

**Look here for:**
- Which UAF document covers which layer → §1.2 `#h3_fido-uaf-documentation`
- Component roles → §2 `#h2_fido-uaf-high-level-architecture`
- Registration and authentication flows → §3.2 `#h3_authenticator-registration`, §3.3 `#h3_authentication`

## Reading guide

**Use this version when:** you are preparing a UAF 1.1 product for certification (UAF 1.1 is the version FIDO certifies) and want the overview that matches the 1.1 document set. Its reading list in §1.2 `#h3_fido-uaf-documentation` names exactly the 1.1 specifications.

**Differences from 1.2:** none in substance. A text comparison shows only the publication date, version links and copyright year differ; every section, figure and sentence of the body is the same. Unlike for some other UAF documents, there is no reason to prefer one edition over the other for this overview.

**Section by section:** structure as in 1.2; see that page's reading guide. In brief: §2 `#h2_fido-uaf-high-level-architecture` describes client, server, abstraction layer (ASM), authenticator and metadata validation; §3 `#h2_fido-uaf-usage-scenarios-and-protocol-message-flows` walks through enrolment, registration, authentication, step-up, transaction confirmation and deregistration as figures; §4 `#h2_privacy-considerations` lists the privacy properties, including attestation keys shared across batches of at least 100,000 units. The document is entirely informative; read fido-uaf-protocol 1.1 for the normative rules.
