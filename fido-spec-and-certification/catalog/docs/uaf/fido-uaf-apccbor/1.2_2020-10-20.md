# FIDO UAF Android Protected Confirmation Assertion Format

Version 1.2 · Proposed Standard · 2020-10-20 · [source](https://fidoalliance.org/specs/fido-uaf-v1.2-ps-20201020/fido-uaf-apccbor-v1.2-ps-20201020.html)

## Summary

This UAF 1.2 document defines the APCV1CBOR assertion scheme, which uses Android Protected Confirmation (APC) to carry out UAF transaction confirmation. With APC, the Android platform shows the transaction text in a trusted UI and signs a CBOR object containing the confirmed prompt.

For registration, the assertion is the normal UAF registration assertion with two constraints: only surrogate basic attestation is allowed, and the Android Key Attestation extension must be present. The self-signature field is empty because the key cannot sign arbitrary data. For authentication, a TLV wrapper (TAG_APCV1CBOR_AUTH_ASSERTION) carries the APC-signed CBOR data together with the AAID, the KeyID and a signature that covers only the CBOR data; the other fields are unauthenticated hints. The processing rules show how the ASM puts the final challenge hash into APC's extraData and the `text/plain` transaction into its prompt text, and how the FIDO Server checks both against the cached transaction. A sample Metadata Statement shows how such an authenticator is described.

This is a new document in UAF 1.2. The tag values are allocated in the UAF Registry 1.2.

**Who needs it:** Android authenticator and ASM developers using Protected Confirmation, FIDO Server developers supporting transaction confirmation
