# Functional Certification: Servers

Source: https://fidoalliance.org/certification/functional-certification/functional-certification-process-servers/ (live text: `python3 scripts/resources.py read functional-certification-process-servers`)
Same content also at: https://fidoalliance.org/certification/functional-certification/functional-certification-servers/


## Summary

Process page for FIDO server vendors seeking Functional Certification. It links the governing FIDO2 Server Requirements v2.3 (WebAuthn Level 3 / CTAP 2.3) and walks through the steps: conformance self-validation with the test tools, interoperability testing at a proctored event or on demand, certification submission with fee payment, optional trademark licensing, and recommended MDS registration. Questions go to the certification team by email.

Official conformance results must be confirmed by the Certification Secretariat at least 14 days before an interop event, and every test, including the metadata service tests, must pass first. Tool access follows the tool request agreement. Servers do not need a Vendor ID; only UAF authenticators do. As of the snapshot the page links two different v2.3 requirement editions (October 2025 and February 2026), both marked active, and its step list carries authenticator-only wording (security levels, authenticator fees) apparently copied from the authenticator page.
